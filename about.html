Swift · Native interfaces

What is ConcordUI?

An open-source, data-driven framework for building native applications from shared Swift code.

ConcordUI lets you define application content, user-interface structure, and behavior in Swift, then present them using each platform’s native user-interface toolkit. Its purpose is to make cross-platform development easier while keeping the look and feel users expect on their devices.

Shared functionality. Native user interfaces.

Your shared code describes what the app contains and how it responds. Apple presents that content through SwiftUI; Android presents it through Jetpack Compose. A button, slider, or selection control follows the platform’s appearance rather than forcing every device into one common visual design.

You can build the shared application without writing the routine SwiftUI or Kotlin host code. ConcordUI’s platform implementations connect your Swift application to the native interface.

How it works

  1. Define your app in Swift. Your Application coordinates startup, navigation, and shared behavior.
  2. Describe the interface as elements. Controls, content, and layout form an element tree.
  3. Organize elements into presentations. Each presentation describes a view.
  4. Display presentations in venues. Venues host content in windows, screens, dialogs, or sheets.
  5. Respond in shared code. User interactions reach your Swift actions, callbacks, and data bindings.

Use your Swift skills

ConcordUI uses familiar Swift ideas: closures for callbacks, bindings for data manipulation, protocols for shared capabilities, and Swift packages for reusable code.

Element flavors let you choose among control styles. For example, a numeric value can use a field, stepper, slider, or combo presentation. You choose the behavior and style in shared code; the platform supplies its native rendering.

Spend less time on repeated setup

The ConcordUI command-line tool creates the shared starter app, generates native platform projects, opens the IDEs, and checks your development environment. Project configuration selects the framework repository and branch, supporting both public and experimental framework work.

Develop in familiar environments: Xcode for Apple and Android Studio for Android. Keep application Swift code and resources in the shared project folders.

Reuse common application experiences

Features provide common experiences such as About, Help, FAQ, Settings, Welcome, Get Started, and What’s New. Configure their shared content and let ConcordUI present it appropriately for each platform.

Platform services give shared code access to application and device information, resources, storage, audio, speech, and other supported native services.

Where ConcordUI fits

ConcordUI is best suited to utilities, productivity tools, and data-driven applications: apps where shared content, controls, and behavior benefit from native platform presentation.

  • Carry existing Swift skills and reusable code into cross-platform development.
  • Reduce repetitive project setup and platform-specific application boilerplate.
  • Use Swift packages alongside your shared application code.
  • Keep native user-interface conventions on each platform.

Current limitations

  • ConcordUI is not designed for games or WYSIWYG editors.
  • A document-based application model is planned but is not available yet.
  • Windows and Linux target support is planned for future development.
  • Available native services and control behavior depend on the platform implementation.

Future expansion discussed in the release presentation includes more elements, such as video, split views, rich-text editors, tables, and data grids. These are future directions rather than current release features.
