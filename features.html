Features

ConcordUI is an open-source, cross-platform user-interface framework for building native applications from a shared Swift application and UI model. This is a current development snapshot and will be updated before release.

Cross-platform architecture

  • Shared Swift application, screen, presentation, container, and element model.
  • Native Apple rendering through SwiftUI and native Android rendering through Jetpack Compose.
  • Current iOS, Android, and macOS validation, with architecture and platform APIs prepared for Windows and other future hosts.
  • Platform, device-class, and orientation detection, plus platform-specific element filtering and hints.
  • Escape hatches for platform-native services when an application needs capabilities outside the portable abstraction.

Application and presentation model

  • ConcordApplication, registered screens, screen navigation, optional data passing, scenes, sections, and presentations.
  • Standard application features including About, Settings, Help, Contact, What’s New, and custom application actions.
  • Standard About presentation using application icon, name, version, build, copyright, acknowledgments, and license links.
  • Primary and secondary venues for presenting application content.
  • Action bubbling from element to scene/screen, section, and application.

Elements and controls

  • Labels, images, semantic standard icons, dividers, horizontal lines, and spacers.
  • Buttons with text, image, combined, round-rectangle, text, and icon presentations.
  • Text and password entry with bindings, change callbacks, placeholders, errors, and regular-expression validation.
  • Boolean controls with switch, checkbox, radio, optional tri-state values, and custom true/false text.
  • Integer and floating-point input with field, stepper, slider, and combo presentations.
  • Date, time, and date-time controls with configurable components and ranges.
  • String, index, string-tagged, and integer-tagged selections with native presentation styles.
  • Determinate and indeterminate progress displays.
  • Enabled, read-only, visible, accessibility, help, error, binding, and change-event capabilities.

Layout and appearance

  • Vertical and horizontal stacks, adaptive AB stacks, work-style stacks, boxes, expanders, spacers, and dividers.
  • Sizing rules, justification, edge spacing and insets, borders, colors, fonts, and platform-native styling.
  • Abstract system and monospaced font families.
  • Responsive layouts that can adapt between portrait mobile and landscape or desktop arrangements.

Data, resources, and platform services

  • Codable, identifiable, sendable Concord data protocols with cloning and value transfer.
  • Portable bindings and typed onChange callbacks.
  • Bundled file, text, PDF, and image resource lookup and retrieval.
  • Open, share, and print services where supported by the host platform.
  • Application name, version, build, copyright, icon, and platform information.
  • Centralized Concord strings designed for future localization.

Developer tooling

  • concordui create for a shared project structure and project metadata.
  • Apple project generation for iOS and macOS, including assets and test targets.
  • Android Studio project generation with Swift/Android bridging and Gradle support.
  • App-icon generation for Apple and Android targets.
  • doctor environment and project checks, plus scoped clean commands and dry-run support.
  • Samples, feature showcases, automated builds, and cross-platform parity validation.
